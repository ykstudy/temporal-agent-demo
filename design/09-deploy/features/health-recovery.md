# 功能：健康检查与恢复

> 实体ID：feature.deploy.health-recovery
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§5.3、§8、§10.1、§13。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-006、R-013、R-018、R-021、R-022、R-023、R-024。
> 基线日期：2026-10-02。

## 目标

使 Harness 自身故障能够被发现并安全恢复，区分接口存活、依赖就绪、Worker 可用与业务阻塞。恢复保留原始身份和已知副作用，不用健康状态替代 Run 完成判断。

## 输入

组件运行信息、Temporal 连接与任务队列、持久存储可读写结果，最后心跳与检查点、未完成 Run、待核实操作台账、恢复授权及依赖变化。

## 输出

带检查时间与原因的存活/就绪结论、降级或阻塞详情、受影响能力与 Run 引用；恢复输出重新校验结果和下一合法阶段，不直接输出交付成功。

## 算法 / 流程

被动检查实际组件与存储，分开报告接口存活和执行能力。重启后恢复权威记录与执行链，核对批准版本、预算、依赖和未确认副作用。结果未知的外部操作先按原身份核实，再决定是否恢复；PAUSED/BLOCKED 沿保存阶段重新验证前置条件，终止态保留，重做创建关联新 Run。对恢复过程追加审计与检查证据。

## 边界与异常

健康探针不创建项目、触发流水线或调用模型完成任务。旧心跳不证明当前 Worker 可用，接口成功也不证明文件存储完整。存储损坏、权限改变、版本缺失或外部结果无法核实须阻塞并说明缺项。取消不回滚既有副作用；未经授权不停止其他项目进程，恢复不能绕过人类门控。

## 被谁依赖


当前基线无其他功能消费本契约；入口/外部使用者在该功能输入与验收中说明。

## 验收标准

分别断开 Temporal、停止自有 Worker、限制存储权限和制造未知外部结果，健康结论准确且不会触发写入。修复后 Run 保留命令、批准、清单和去重信息，只恢复合法阶段；终止 Run 不因重启复活。
