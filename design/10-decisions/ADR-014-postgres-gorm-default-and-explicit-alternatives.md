# ADR-014 PostgreSQL / GORM 默认与显式候选配置

> 实体ID：adr.014
> 来源：[原设计](../../docs/PRODUCT-GUIDE.md)：§2.3、§7.2、§7.5；L71、L877–920、L1122–1147。
> 审校：[裁决记录](../../docs/analysis/REVIEW-DECISIONS.md)：R-009、R-017、R-020。

## 状态

accepted。生效日期为 2026-10-02；这是本次有效设计基线，不将来源示例、已有代码或测试结果追认为过去的批准。

## 背景

原文列出 postgres/mysql/sqlite 与 gorm/sqlx，但没有为默认项目规定可预测组合。直接按缺省值猜测驱动或连接配置，会让预览、生成代码和运行时依赖出现不同理解。

## 决策

数据库技能选择 PostgreSQL 与 GORM 作为明确默认。MySQL、SQLite 和 sqlx 作为登记候选，通过显式参数切换并核验支持矩阵、驱动版本和平台要求；不因连接失败自动改数据库，也不内置真实 DSN 或密码。

## 理由

固定默认减少首轮澄清而不剥夺用户选择。代码生成、编译和隔离连接/迁移测试分别记录，客户目标标记未执行，避免把六种组合能编译当作客户数据库已配置成功。

## 备选方案

仅提供一种数据库更简单但不覆盖原能力；自动探测机器上的服务缺少可审查来源；连接失败切到 SQLite 会改变数据语义。候选均应出现在确认方案中。

## 影响

首版只生成库/ORM 配置与迁移入口，并在登记的隔离 DB 测试；普通项目批准不能授权客户 DB 连接或迁移。客户数据库动作属于未来扩展，须新 ADR、精确目标、独立批准及未知结果核实契约。验收各组合、缺配置、脱敏与客户 DSN 拒绝，隔离通过不冒称客户可用。
