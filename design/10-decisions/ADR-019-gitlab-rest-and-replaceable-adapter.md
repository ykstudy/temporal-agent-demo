# ADR-019 GitLab REST 契约与可替换适配器

> 实体ID：adr.019
> 来源：[原设计](../../docs/PRODUCT-GUIDE.md)：§1.2、§7.3–7.4、§9.2；L19、L925–1073、L1212–1216。
> 审校：[裁决记录](../../docs/analysis/REVIEW-DECISIONS.md)：R-005、R-007、R-019、R-024。

## 状态

accepted。生效日期为 2026-10-02；这是本次有效设计基线，不将来源示例、已有代码或测试结果追认为过去的批准。

## 背景

原设计列出 xanzy/go-gitlab 包名，但 SDK 包名不构成长期可用性、权限或接口兼容保证。业务需要的是可核实的项目、提交和流水线行为，不能在本轮文档中盲照旧依赖或宣称已查新。

## 决策

集成公共契约以 GitLab REST 的请求语义、目标身份、状态码、响应身份与核实证据定义，SDK 或受控 HTTP 实现均可替换。选用适配器时固定具体依赖版本并验证实例兼容，原 xanzy 包仅保留为来源记录。

## 理由

接口语义与实现库分离可保持产品门禁稳定，也让自建 GitLab 实例差异能被隔离验证。固定依赖避免恢复时适配行为静默变化，但不能替代真实实例测试。

## 备选方案

继续复制原包路径缺少维护和兼容证据；运行时自动选择 SDK 会漂移；为单一库重写产品契约增加耦合。允许适配器更换但拒绝省略身份与错误分类。

## 影响

适配器验收包含权限失败、明确不存在、限流、响应缺字段和写结果未知；凭据仅在受控执行器使用。未配置真实实例时标记未配置或阻塞，HTTP mock 通过不冒称 GitLab 端到端成功。
