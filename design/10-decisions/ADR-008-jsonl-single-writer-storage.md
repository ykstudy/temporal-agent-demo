# ADR-008 首版 JSONL / 快照与单写者部署边界

> 实体ID：adr.008
> 来源：[原设计](../../docs/PRODUCT-GUIDE.md)：§1.2、§4.3、§6.1、§9.2；L21、L183、L600–637、L1212–1216。
> 审校：[裁决记录](../../docs/analysis/REVIEW-DECISIONS.md)：R-014、R-018、R-023。

## 状态

accepted。生效日期为 2026-10-02；这是本次有效设计基线，不将来源示例、已有代码或测试结果追认为过去的批准。

## 背景

原文使用本地 JSONL 并按 Run 索引，但忽略序列化、扫描、同步和并发覆盖错误。本机文件不会因 Workflow 有持久历史就自然成为其他 Worker 可读取的恢复数据。

## 决策

首版保留追加 JSONL 与原子替换快照，限定单写者部署或有明确锁/CAS 的等价控制。稳定消息身份、快照版本、存储引用和部分提交修复记录构成恢复协议；跨 Worker 使用共享持久存储或独立服务，不承诺跨文件事务。

## 理由

保留简单存储便于初版交付，同时如实限制其一致性与运维能力。写入失败须失败关闭，不能先返回成功再让下次读取发现记录缺失；Temporal 只保证它自身记录的历史。

## 备选方案

立即引入分布式数据库增加迁移成本，可作为后续替换；多个进程直接共写文件最简单但缺少一致性；仅依赖进程内锁不能满足跨实例写者互斥。

## 影响

部署文档声明目录权限、持久卷、备份恢复与 retention。故障注入覆盖截断尾记录、磁盘失败、快照替换中断和锁冲突；无法核实的部分提交报告明确恢复状态，不静默丢消息。
