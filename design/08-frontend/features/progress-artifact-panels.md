# 功能：进度与工件面板

> 实体ID：feature.frontend.progress-artifact-panels
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§4.1、§4.3、§7.5、§10.1、§13。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-006、R-007、R-009、R-019、R-023、R-024。
> 基线日期：2026-10-02。

原文提供状态、产物引用和检查结果，面板组织属于新增展示设计。当前工作区阶段/产物/历史及有限浏览器证据见[实现状态](../../../docs/analysis/IMPLEMENTATION-STATUS.md)和[浏览器验收](../../../docs/evidence/BROWSER-QA.md)，完整检查与身份展示仍按本文契约验收。

## 目标

使用户了解项目创建当前阶段、等待原因、验证结果及可取得的工件。面板服务 Go 脚手架、GitLab 与 CI 交付，不提供生产部署状态或用固定动画暗示实际进展。

## 输入

接收业务 Run、阶段检查点、详细操作进度、阻塞原因、工件清单、仓库身份、提交 SHA、流水线身份与必需检查结果。每组结果携带来源版本及执行、决策、交付模式，不能混用其他 Run 的记录。

## 输出

输出可查阅的阶段、已确认结果、失败详情和工件入口。仓库、提交与 CI 分别显示实际证据；本地验证与远程验证分别表达，未执行或缺证据的检查保留在列表中。

## 算法 / 流程

按状态同步契约更新面板，将 Workflow 阶段与 Activity 详细进度分开呈现。读取检查集合逐项显示结果，再引用服务端的最终完成判断。打开工件时提交其稳定引用，显示批准版本与文件摘要，并使用工件浏览契约取得内容或下载。

## 边界与异常

按交付模式固定检查集：local 要求清单、真实测试构建及下载包证据，gitlab 额外要求确认提交和匹配流水线。必要项缺失显示未就绪，其他项通过不能使它完成。未知结果保留待核实，取消不说明副作用撤销；读取失败与错误脱敏。执行模式 local 不作 Temporal 持久执行证据，决策模式 rules 不作模型调用证据，本地交付不证明远程验证。

## 验收标准

缺检查输入、CI 失败、另一 SHA 的成功流水线及工件读取失败均得到正确展示，不能出现整体成功。批准版本、工件摘要、提交和流水线可对应同一次任务；断线后面板标明数据新鲜度，恢复后以权威结果收敛，不重复触发外部操作。
