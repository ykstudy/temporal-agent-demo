# 功能：可访问交互

> 实体ID：feature.frontend.accessibility
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§3、§5.4、§12。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-002、R-011、R-019、R-024。
> 基线日期：2026-10-02。

原文只提出对话入口，未规定键盘、读屏或响应式细节；以下是新增规范目标。当前桌面与窄屏浏览器证据见[实现状态](../../../docs/analysis/IMPLEMENTATION-STATUS.md)和[浏览器验收](../../../docs/evidence/BROWSER-QA.md)，不证明完整键盘、读屏或可访问性认证。

## 目标

使用户通过键盘、辅助阅读和不同屏幕尺寸完成同等的项目创建交互，能理解提案范围、等待状态、失败原因及结果。可访问方式须保留相同确认边界，不取得额外操作权限。

## 输入

接收工作区结构、可操作权限、消息正文、方案摘要、命令回执和进度工件内容。输入包含控件名称、状态含义及执行、决策模式，敏感字段在进入可访问呈现前完成脱敏。

## 输出

输出具有可读名称、逻辑阅读顺序、明确焦点和文字状态说明的界面。错误与待确认内容可被发现，代码及结构图提供可阅读表达；local、temporal、rules、model 的差异不能只用颜色或图标区分。

## 算法 / 流程

按任务操作顺序组织焦点与阅读结构，提交后关联对应回执。明确打开或关闭审阅区域时管理焦点，流式更新不持续抢走正在输入的位置；将重复进度播报合并，保留批准范围、版本及最终结果的完整说明。

## 边界与异常

长文本、缩放和窄屏不得遮挡确认、拒绝或错误说明。禁止只靠颜色表达成功、失败及过期状态；禁用控件说明原因，但客户端禁用不能替代服务端权限校验。凭据不进入替代文本或播报，断线与待核实结果不能被宣布为完成。

## 被谁依赖


当前基线无其他功能消费本契约；入口/外部使用者在该功能输入与验收中说明。

## 验收标准

仅用键盘可选择 Run、发送消息、审阅方案、确认或拒绝及查阅工件，焦点可见且不会困在面板。读屏能区分待提交、已接收、已批准与已应用，流式更新不干扰编辑；缩放和窄屏仍保留主要操作。上述检查需实际浏览器证据，文档或 setup 不算通过。
