# 文档认知模型 Schema 与校验边界

认知模型只登记文档结构和关系。领域职责、功能目标、算法、状态、权限和验收正文保存在对应 Markdown 中；YAML 不保存第二份正文，也不承载运行中的 Task DAG 或 Run 状态。

## 实体

`entities.yaml` 顶层只允许 `schema_version: 1` 和 `entities` 序列。每个实体的必填字段是 `id`、`type`、`name`、`path`；功能额外必填 `domain`，其他实体不能设置 `domain`。这五个字段是完整白名单。

| 字段 | 约束 |
|---|---|
| `id` | 非空、唯一的稳定字符串 |
| `type` | `domain`、`feature`、`adr` 或 `invariant` |
| `name` | 非空显示名称，不复制正文 |
| `path` | 相对 `design/` 的 Markdown 文件路径，可附已有锚点；不能越界 |
| `domain` | 功能所属领域 ID，必须能解析为一个 `domain` |

必须有九个领域。每个功能必须有唯一且与 `domain` 字段一致的 `belongs_to` 关系。一个功能文件不能登记为多个功能；`*/features/*.md` 和 `10-decisions/ADR-*.md` 必须登记，不能留下未纳入模型的功能或 ADR。

冻结不变量文件中每个 `INV-xxx` 标题都必须登记为同 ID 的 `invariant`，路径精确指向该文件的对应标题锚点；漏登、登记到错误锚点或伪装成其他类型均拒绝。标题中的不变量 ID 也不能重复。功能、ADR 的物理路径按其真实类型核对，不能改登记类型绕过章节和关联检查。

功能文件的二级章节必须按顺序完整包含且仅包含八节：目标、输入、输出、算法 / 流程、边界与异常、依赖、被谁依赖、验收标准。ADR 必须按顺序完整包含且仅包含：状态、背景、决策、理由、备选方案、影响、关联、历史。合法缩进的 ATX 标题与 Setext 二级标题都纳入计数，不能用排版方式隐藏额外章节。

## 关系

`relations.yaml` 顶层只允许 `schema_version: 1` 和 `relations` 序列。关系必填 `from`、`to`、`type`，可选 `contract`；其他字段拒绝。端点必须登记，完全相同的关系不能重复，不能自引用。

| 类型 | 方向与含义 |
|---|---|
| `belongs_to` | 功能 → 领域；唯一领域归属 |
| `consumes` | 消费目标的输出；功能之间必须设 `contract: 输出` |
| `submits_to` | 向目标的输入提交请求或交付；功能之间必须设 `contract: 输入` |
| `decides` | ADR → 领域或功能；记录决策关联 |
| `constrains` | 不变量 → 领域或功能；记录适用范围 |
| `depends_on` | 仅用于非功能契约结构关联；禁止功能 → 功能，不能当作运行 Task DAG |

仅功能之间的 `consumes`、`submits_to` 可携带 `contract`。每条此类关系必须对应源功能“依赖”中的目标功能相对链接，精确指向 `#输出` 或 `#输入`；依赖不能定位目标的算法或其他内部章节。

功能之间任何依赖都必须采用 `consumes` 或 `submits_to` 的公开契约；即使删去正文依赖和逆向链接，也不能用 `depends_on` 保存一条绕过契约检查的功能依赖。

反向引用由同一条模型关系核对：`consumes` 的目标在“被谁依赖”中链接源功能 `#输入`；`submits_to` 的目标在“被谁依赖”中链接源功能 `#输出`。漏写、额外写入但未登记的引用、方向错误都拒绝。契约影响关系允许反馈环；这不表示运行 Task DAG 允许有环。

每个 ADR 至少有一条指向领域和一条指向功能的 `decides` 关系，且其“关联”节包含这些目标文档的有效相对链接。

## 来源与冻结摘要

`constraints.yaml` 顶层只允许 `schema_version: 1`、`baseline` 和 `checks`。`baseline` 必须有以下四个字段，路径相对项目根目录；本项目原文和不变量路径固定为示例中的两个文件，不能改指其他文档绕过检查：

```yaml
schema_version: 1
baseline:
  source: docs/PRODUCT-GUIDE.md
  source_sha256: "原始设计文档完整字节的 SHA-256，64 位小写十六进制"
  invariants: design/00-invariants/INVARIANTS.md
  invariants_sha256: "有效不变量完整字节的 SHA-256，64 位小写十六进制"
checks:
  - id: unique-entities
    kind: entities
    description: 实体标识唯一，路径与类型合法
```

`checks` 每项只允许非空字符串 `id`、`kind`、`description`，`id` 不重复。它是检查目录，不是可关闭校验规则的程序语言；校验器始终执行全部内置结构约束。

摘要按原始字节计算，包含空白、换行和编码。冻结只通过摘要核对，不由工具重写或自动更新；来源或不变量变化会失败，不能借更新摘要隐藏未经授权的规则变化。

## 本地链接与锚点

检查 `design/` 下全部 Markdown 的本地相对链接，允许指向项目内已有文档、文件和图片。禁止路径或符号链接解析后越出项目根。Markdown 标题锚点保留中文字符，英文转小写，移除标点，空格换为连字符；重复标题增加 `-1`、`-2`。例如“算法 / 流程”对应 `#算法--流程`，但功能依赖只能链接 `#输入` 或 `#输出`。

围栏代码块、缩进代码块、行内代码和 HTML 注释中的示例链接不作为实际引用检查。外部网址不做网络可用性判断；本地引用式链接、图片链接和 HTML `href` / `src` 也纳入检查。引用式链接的定义在整篇文档内解析，章节可使用文档尾部的定义；没有被使用的定义不制造依赖关系。

## 执行与错误注入

从项目根运行：

```sh
python3 design/_model/check.py
python3 design/_model/check.py --json
python3 design/_model/check.py --self-test
python3 design/_model/check.py --root /path/to/project --self-test --json
```

成功退出码为 `0`，结构、来源或测试失败为 `1`。有 PyYAML 时使用安全加载器并拒绝重复键；没有 PyYAML 时使用标准库严格解析本 Schema 所需的映射、序列、标量、引号和 JSON 内联结构。后备解析器不支持 YAML 标签、别名及块字符串；可用单行引号字符串表示检查描述，无需安装依赖。

`--self-test` 首先要求真实文档基线通过，再在临时副本中分别注入七类错误：原始设计与冻结不变量字节变化、实体文件丢失、ID 重复、关系悬空、依赖内部章节、ADR 缺少关联、结构模型混入正文或运行流程。第一类要求两个摘要变化都被捕捉。副本会自动清理，不修改源文档或冻结摘要。

同一命令另运行四项防绕过回归，并作为 JSON 的 `guard_tests` 或文本 `GUARD-TEST` 输出：删除公开正向/逆向链接后用功能 `depends_on` 替代契约关系；删掉不变量实体及其所有关系；把真实功能或 ADR 文件改登记为 `invariant`。四项都必须被拒绝；总退出码同时覆盖七类负例与四项回归。

本结构模型没有运行 Task DAG，第七项通过拒绝循环 Workflow 数据写入实体的内容污染来验证结构边界；不将这个结果表述为运行 DAG 的循环检测证明。

## 证明范围

校验通过只证明文档结构、来源摘要与认知模型一致。它不能证明产品状态机、权限、预算、重试、外部副作用或运行验收已实现；产品行为仍需独立的实现、真实测试和执行证据。校验器在每次输出中明确声明这一边界。
