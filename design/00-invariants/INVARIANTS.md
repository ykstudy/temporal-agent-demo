# 项目创建 Agent — 有效不变量基线

基线日期：2026-10-02。来源：[原设计](../../docs/PRODUCT-GUIDE.md)、[审校裁决](../../docs/analysis/REVIEW-DECISIONS.md)。原文保持原样；本文件是在用户授权自主纠错补漏后建立的新基线，纠错条目不伪称逐字原文。冻结生效后不直接改字，通过 ADR 和显式批准修订；完整字节摘要保存在[结构约束](../_model/constraints.yaml)。

## INV-001 项目创建范围

描述：本产品通过多轮对话创建 Go 项目、应用登记技能、初始化 GitLab 仓库并验证 CI 首跑；本期不包含既有业务项目自主修改、客户数据库实际迁移、合并上线或生产发布。

来源：§1.1、§2.3、§12；R-012、R-024。

约束对象：全部领域。

违反后果：普通项目确认被扩大为生产授权或两产品职责混合。

例外：扩展范围须新增 ADR、独立门禁与契约。

## INV-002 Workflow 确定性

描述：Workflow 只用 Temporal SDK 确定性原语维护控制流程；模型、文件、网络、进程及外部时间随机结果通过 Activity 获取。

来源：§3、§5.2；R-001。

约束对象：编排、Agent、集成。

违反后果：重放不一致、原生同步阻塞或不可恢复执行。

例外：HTTP 服务和 Activity 可使用常规 Go 并发设施。

## INV-003 语义建议与控制权分离

描述：模型只提出结构化意图、参数和动作建议；合法状态、权限、预算、批准和完成均由确定性规则裁决。

来源：§5.1–5.2；R-010。

约束对象：Agent、编排、治理。

违反后果：模型自授权限或以自身声明越过验证。

例外：无。

## INV-004 运行定义不漂移

描述：每个 Run 固定 AgentDefinition、模板、Skill、动作 Schema 与工具版本引用；批准内容不得因 Worker 升级静默变化。

来源：§2.1、§2.3；R-011、R-017。

约束对象：Agent、技能、编排。

违反后果：恢复时执行与已审查方案不同。

例外：更换定义产生新提案或关联新 Run，不修改旧批准。

## INV-005 业务 Run 身份稳定

描述：业务 agent_run_id 在消息、工件、审批、审计和 Continue-As-New 链中保持稳定；Temporal execution RunID 只标识执行段。

来源：§2.2、§4、§5.3；R-003、R-004、R-013。

约束对象：编排、对话、可观测性。

违反后果：跨执行段丢失归属或多个任务串上下文。

例外：重做创建有原 Run 关联的新业务身份。

## INV-006 副作用身份稳定

描述：写操作身份绑定业务 Run、操作类型、批准来源版本和操作序列；重试与 Continue-As-New 保留原操作身份及目标指纹。

来源：§4.4、§7.3、§8.3；R-004。

约束对象：治理、技能、集成。

违反后果：同一请求重试产生多个外部对象。

例外：已批准新版本或新增操作须生成不同身份。

## INV-007 消息可去重可追溯

描述：每条命令有稳定身份、Run 归属和内容摘要；同身份同内容返回既有结果，同身份不同内容返回冲突。

来源：§4.2、§5.4、§13.8；R-003。

约束对象：对话、编排。

违反后果：网络重发重复推进或错误 Run 接收消息。

例外：无。

## INV-008 命令串行与有界背压

描述：每个 Run 的权威接收点分配顺序号并串行消费；队列容量有限，满时返回明确等待或拒绝，不能无提示丢失命令。

来源：§3、§5.2、§13.8；R-001、R-003。

约束对象：编排、对话。

违反后果：并发确认造成覆盖、重复轮次或内存失控。

例外：不同 Run 可在隔离资源和总预算内并行。

## INV-009 预览先于应用

描述：项目方案以未应用 Proposal 展示文件差异、能力、影响、规则结果和外部目标；未确认预览不生成真实项目工件或执行外部写入。

来源：§2.1–2.2、§5.2；R-011；参考预览契约方法。

约束对象：对话、技能、编排。

违反后果：不可审查的副作用提前发生。

例外：保存提案和对话记录属于审阅元数据，不是项目应用。

## INV-010 确认绑定当前对象

描述：确认必须绑定用户身份、Run、proposal_id、proposal_version、source_version、动作范围和有效期；接受及首次应用前重校验。source_version 仅随方案内容或授权范围变更，普通阶段/进度变化使用 state_sequence；proposal_version 的内容不可变。issued_at/expires_at 由服务端签发，默认 30 分钟，可配置 1 分钟至 24 小时，客户端不能延期。有效期内开始的固定批准动作链可以在原范围内完成，但每步复核来源、权限和预算；超期后的新增范围须重新批准，不撤销已核实事实。旧版本、过期首次应用、关闭提案和越权确认均拒绝。

来源：§5.4、§9；R-011。

约束对象：编排、对话、治理。

违反后果：旧确认覆盖新内容或重复应用。

例外：同一已应用确认重试仅返回既有结果。

## INV-011 批准范围明确

描述：项目确认只授权列明的工作区、仓库和 CI 操作；配置连接、普通聊天“可以”、模型文本和文档审阅批准不能替代业务执行批准。

来源：§1.1、§9.2；R-011、R-012。

约束对象：治理、对话、集成。

违反后果：普通动作绕过高权限或扩展环境范围。

例外：未来合并/生产发布须独立审批，不继承普通确认。

## INV-012 状态转移封闭

描述：合法状态为 INTAKE、CLARIFY、PLAN、IMPLEMENT、VERIFY、DELIVER、DONE、PAUSED、BLOCKED、FAILED、CANCELLED；只按本文件状态/事件表推进，未列事件拒绝。

来源：§4.1、§5、§8；R-010、R-022。

约束对象：编排、前端。

违反后果：模型或客户端任意跳阶段。

例外：DELIVER 内可登记 remote_repo、remote_ci、package 子步骤。

## INV-013 暂停与恢复保留事实

描述：暂停在安全阶段边界生效并保存 resume_to、批准、完成和操作记录；恢复校验来源、权限、预算与核实证据后返回保存阶段。

来源：§5.4、§8；R-021、R-022；新增补全。

约束对象：编排、集成。

违反后果：暂停被当作回滚、重复阶段或恢复到错误任务。

例外：执行中的不可中断副作用先核实再进入暂停。

## INV-014 终止不原地复活

描述：DONE、FAILED、CANCELLED 为终止态；重做创建关联新 Run 并重新预览确认。拒绝未应用提案关闭该提案并回 CLARIFY，不自动终止整个 Run。

来源：§5、§8、§13；R-022。

约束对象：编排、对话。

违反后果：已结束任务被复活、旧审批重新生效。

例外：终止后仍可只读查询、导出和核实已有副作用。

## INV-015 结果未知先核实

描述：外部操作结果分为未执行、成功、明确失败、未知；未知进入 BLOCKED，并按原操作身份核实，不能把超时或取消当成未执行并盲重放。

来源：§8.3、§7.3–7.4；R-006。

约束对象：编排、集成。

违反后果：重复建仓、推送或触发 CI。

例外：只有证据确认未执行后才允许安全重试。

## INV-016 外部目标精确绑定

描述：GitLab 实例、namespace/path、project_id、分支及本任务所有权均须绑定；仅明确不存在才创建，不接管无本任务证据的同名仓库。

来源：§4.4、§7.3、§8.3；R-005。

约束对象：集成、治理。

违反后果：误接管他人项目、把查询失败当不存在。

例外：被显式批准的既有仓库接入需另行契约和所有权检查。

## INV-017 验证绑定来源版本

描述：本次批准文件 manifest、提交 SHA、ref、pipeline ID 和报告必须关联同一版本；不能用分支存在或最新流水线成功代替本次验证。

来源：§7.4–7.5；R-007。

约束对象：集成、可观测性。

违反后果：其他提交成功被误判成本次成功。

例外：复用相同 SHA/ref 的已确认流水线必须登记复用证据。

## INV-018 完成需要固定检查集合

描述：完成条件按交付模式预先确定 required_checks，缺输入或缺证据不能省略检查；验证独立于模型和执行器成功声明。

来源：§7.5、§13；R-008、R-009。

约束对象：可观测性、编排、集成。

违反后果：检查缺失却因剩余项通过被判完成。

例外：仅 delivery_mode=local 明确跳过远程事项，仍须本地构建测试与工件完整性；execution_mode=local 且 delivery_mode=gitlab 仍须真实远程检查。

## INV-019 工件完整与原子登记

描述：项目工件包有业务身份、批准版本、模板/技能参数摘要、文件 hash、验证与来源引用；仅完成标记存在不能证明全部成功。

来源：§4.3、§7.1–7.2；R-017。

约束对象：技能、对话、可观测性。

违反后果：部分文件写入被标成功、旧参数被复用。

例外：恢复发现部分写入须核实修复，不能重新声明未发生。

## INV-020 工作区严格隔离

描述：所有文件和进程目标限定在获准 Run 工作区；规范化路径并拒绝越界、非法绝对路径与未经批准的符号链接。

来源：§7.1–7.2、§9.2；R-017、R-020。

约束对象：治理、技能、对话。

违反后果：写入其他项目或读取未授权文件。

例外：允许读取已登记的只读模板源，不扩大写边界。

## INV-021 密钥不进入数据平面

描述：GitLab 与模型凭据只在受控执行器读取；不进入模型上下文、Workflow payload/header、命令参数、git remote、工件、日志或对话。

来源：§7.3、§9.1；R-019。

约束对象：治理、集成、Agent、运维。

违反后果：凭据落盘或通过历史/进程列表泄漏。

例外：凭据运输只能使用经审查的服务端凭据机制。

## INV-022 权限最小化且可核实

描述：能力和操作按身份、目标、环境及动作授权；实例与 token 能力有明确验证，不能把原文两个 scope 字符串视作跨部署通用保证。

来源：§9.2；R-012、R-019、R-020。

约束对象：治理、集成、运维。

违反后果：配置连接被当作授权任意写入。

例外：权限提升必须有新批准及审计。

## INV-023 工具命令白名单

描述：Skill post hook 和构建工具使用登记命令/参数/版本及资源边界；用户或模型字符串不能直接变成任意 shell。

来源：§7.2、§9；R-020。

约束对象：技能、治理。

违反后果：任意命令执行、依赖或工具版本漂移。

例外：新增工具经定义版本和权限审查登记。

## INV-024 原始对话追加保存

描述：原消息不可被模型摘要覆盖；JSONL 原文和稳定身份持续保留，摘要作为可追溯派生记录，损坏/写失败必须显式报告。

来源：§6.1、§6.3；R-014、R-018。

约束对象：对话、Agent、运维。

违反后果：审计证据丢失或静默截断。

例外：保留期清理遵循显式策略和审计，不以压缩为由删除。

## INV-025 授权真相不依赖摘要

描述：权限、批准、预算、完成条件、安全约束、当前版本和阻塞原因来自结构化权威记录；摘要不得生成或继承批准结论。

来源：§6.3；R-014。

约束对象：Agent、治理、编排。

违反后果：有损或错误摘要改变授权与完成条件。

例外：摘要可概括业务讨论并引用权威记录。

## INV-026 上下文预算硬约束

描述：请求保留固定规则、完整当前消息和权威状态并预留协议/输出空间；按层裁剪，必要层超限明确拒绝，保持 UTF-8 完整。

来源：§2.2、§6.2；R-015。

约束对象：Agent、治理。

违反后果：尾部截断丢需求、token 超限、约束丢失。

例外：无 tokenizer 时采用标明的保守上界，不伪称精确 token。

## INV-027 大对象只传稳定引用

描述：Workflow 与 Activity 交换小体积结构数据，大文档/对话/工件仅传可验证的引用、版本和摘要，引用在目标 Worker 可访问。

来源：§4.3、§6.1–6.2；R-018。

约束对象：编排、对话、运维。

违反后果：Temporal 历史膨胀或恢复找不到对象。

例外：容量边界内的命令必要字段可直接传递。

## INV-028 文件持久化边界显式

描述：首版 JSONL/快照限定单写者或显式锁/CAS；快照原子替换，存储错误失败关闭；跨 Worker 恢复需要共享持久存储、备份和访问约束。

来源：§1.2、§6.1、§9.2；R-018。

约束对象：对话、运维。

违反后果：把本机临时文件等同持久恢复、并发覆盖。

例外：存储后端替换须 ADR 和迁移/恢复验收。

## INV-029 检查点迁移完整

描述：Continue-As-New 保留业务身份、定义/源版本、参数、摘要和原文引用、去重账本、操作身份、等待/暂停和恢复目标；迁移前 handler 和队列排空或已持久登记。

来源：§5.3；R-013。

约束对象：编排、对话、Agent。

违反后果：新执行遗漏消息或重新执行已批准动作。

例外：达到历史限制前可按确定阈值切段，阈值只属于执行策略。

## INV-030 失败分类与修复有界

描述：基础设施暂时错误、业务失败、永久/权限错误和结果未知分别处理；明确尝试次数、总期限、心跳与模型修订预算，未知状态优先核实。

来源：§8.1–8.2；R-021。

约束对象：编排、Agent、集成。

违反后果：无限重试或安全错误被当作普通修复。

例外：明确策略批准的人工新尝试仍保留原失败证据。

## INV-031 模式与能力如实声明

描述：Temporal 与 local、模型调用与规则解析、远程交付与本地下载分别展示；未配置的外部能力保持阻塞或按获准本地范围交付，不虚构外部成功。

来源：§1、§12–13；R-023、R-024；新增边界。

约束对象：前端、运维、编排。

违反后果：样例/本地执行被误报为真实线上验收。

例外：本地演示可以存在，但不能复用 Temporal 持久保证。

## INV-032 展示消费权威响应

描述：客户端只提交意图并显示服务端确认的版本和状态；本地草稿/发送中、命令已接收、操作已完成和任务已完成分别表达。

来源：§3、§5.4、§10.1；R-002、R-023。

约束对象：前端、对话。

违反后果：乐观成功、断流误完成或跨 Run 串消息。

例外：草稿和选中状态可本地即时变化。

## INV-033 审计与传播边界

描述：关键动作有 Run/操作/版本、原因、脱敏结果和时间/关联证据；传播只携带经校验非敏感标识，不承担授权真相。

来源：§6.4、§9.3、§10；R-016、R-019。

约束对象：可观测性、治理。

违反后果：历史无法归属或 header 传播凭据/批准。

例外：不支持传播时用显式字段，不能声称链路已实现。

## INV-034 文档模型只存结构

描述：文档认知模型仅登记域、功能、ADR、不变量的身份、名称、路径与关系；业务正文、运行状态和运行 DAG 不复制到 YAML。

来源：参考五层结构方法；R-024；本次新增文档约束。

约束对象：全部设计文档、文档工具。

违反后果：产生两份内容真相或把文档关系误当运行合规。

例外：运行模型若扩展，须独立 Schema 与验收。

## INV-035 冻结规则受控修订

描述：本次审校后的不变量建立 SHA-256 基线；后续变更以 ADR 描述旧新规则、理由和影响，并经显式范围批准更新冻结基线，禁止校验器自动刷新摘要。

来源：参考冻结规则方法；本次新基线授权。

约束对象：不变量、ADR、文档校验。

违反后果：规则被静默改写或通过改摘要掩盖违规。

例外：原文保留作为证据，本次自主纠错记录为新规则。

## INV-036 技能注册与职责闭合

描述：首版登记 add_database、add_auth、add_logging；Skill 描述参数 Schema、支持栈、输入输出、权限与验证，执行不能发明未登记能力。

来源：§2.3、§7.2；R-017、R-020。

约束对象：技能、Agent、治理。

违反后果：未知技能绕过参数或权限检查。

例外：新技能以版本化注册和新契约扩展。

| INTAKE | 参数缺失→CLARIFY；方案完整→PLAN；取消→CANCELLED；不可恢复→FAILED | 分配业务身份和定义引用 |
| CLARIFY | 补充后完整→PLAN；继续补充→CLARIFY；暂停→PAUSED；取消→CANCELLED；不可恢复→FAILED | 不执行项目写入 |
| PLAN | 有效确认→IMPLEMENT；修订/拒绝→CLARIFY；新预览→PLAN；暂停→PAUSED；取消→CANCELLED；不可恢复→FAILED | 当前 proposal/source 版本、权限、有效期全部通过 |
| IMPLEMENT | 文件/技能完成→VERIFY；安全暂停→PAUSED；未知/外部依赖→BLOCKED；不可恢复→FAILED；安全取消→CANCELLED | 登记工件 manifest，不以 marker 代替完整性 |
| VERIFY | 必需本地检查通过→DELIVER；同一批准快照的安全重试→IMPLEMENT；批准内容修订→PLAN；依赖未就绪→BLOCKED；安全暂停→PAUSED；不可恢复→FAILED；安全取消→CANCELLED | 修改文件/参数/范围先产生未应用预览并重新批准，不用旧批准授权修复 |
| DELIVER | 子步骤推进→DELIVER；所有必需检查及包完整→DONE；未知/缺配置→BLOCKED；安全暂停→PAUSED；不可恢复→FAILED；安全取消→CANCELLED | remote_repo→remote_ci→package，delivery_mode=local 显式跳过远程子步骤 |
| PAUSED | 恢复→已保存非终止状态；取消→CANCELLED；永久失效→FAILED；来源/授权失效→PLAN | 不能任意选择恢复阶段；需重新批准时停止旧执行 |
| BLOCKED | 核实/依赖恢复→已保存非终止状态；来源/授权失效→PLAN；取消→CANCELLED；不可恢复→FAILED | 未知保持阻塞，确认未执行后才重试 |
| DONE | 只读查询/导出；重做→关联新 Run | 当前 Run 不发生执行转移 |
| FAILED | 只读查询/核实；重做→关联新 Run | 新尝试不继承旧批准为新版本授权 |
| CANCELLED | 只读查询/核实；重做→关联新 Run | 不声明外部写入已经撤销 |

任何未列转移默认拒绝；只读查询不改变状态。暂停、取消、恢复携带命令身份，核实待定副作用属于原 Run 的证据维护，不等于终止态复活。

## 确认与质量门禁

| 门禁 | 定义者 / 裁决者 | 必要证据 | 失败处理 |
| --- | --- | --- | --- |
| P0 方案规则检查 | 治理定义，确定性校验器裁决 | 参数、命名、技能依赖、目标、范围、预算和来源版本 | 提案 blocked，不应用 |
| P1 项目方案确认 | 用户批准，编排/治理复核 | proposal/source 版本、身份、范围、有效期、内容摘要 | 过期/拒绝回澄清或重新预览 |
| E1 本地验证 | 独立验证契约 | required_files、manifest、真实测试/构建及秘密检查 | 有界修复或失败，不能直接交付 |
| E2 远程首跑 | GitLab 集成产生事实，验证契约裁决 | project_id、ref、commit SHA、pipeline ID 与真实终态 | 待运行不完成；结果未知先核实 |
| D1 交付完成 | 编排消费独立证据 | 按模式固定的 required_checks、工件包、报告、全部来源版本一致 | 缺证据停留当前阶段或阻塞 |

delivery_mode=local 的 E2 标记“不适用 / 未执行”，不能标为“远程通过”。这些是本项目命名；不借用参考 harness 的生产 G3/G4 作为已支持能力。

## 权限与职责矩阵

| 角色 | 可以做 | 不可以做 |
| --- | --- | --- |
| 用户 | 提交需求、查看预览、批准具体范围、暂停/取消、申请重做 | 用旧确认批准新内容或把普通确认扩大到生产 |
| 客户端 | 维护草稿、提交带身份/版本的意图、展示权威响应 | 自行推进状态、伪造确认/完成、读取服务端凭据 |
| Agent/模型 | 澄清、结构化建议、方案和摘要草案 | 直接写项目/创建仓库、自授权限、生成完成事实 |
| 确定性控制平面 | 校验状态、版本、批准、预算并调度合法 Activity | 把模型话语当授权，跳过独立验证 |
| Skill/外部执行器 | 在批准范围内访问隔离工作区和精确外部目标 | 任意 shell、读取无关文件、泄露凭据、未经核实重复写 |
| 独立验证器 | 读取登记证据并形成具体检查结果 | 修改批准、把缺证据省略或把别的提交成功当本次成功 |
| 运维 | 配置服务/凭据引用、备份与恢复、观察健康 | 把连接配置当用户对所有项目操作的授权 |
| 文档审阅工具 | 浏览结构、生成差异、登记批准的设计版本 | 把设计批准当运行批准、修改原始来源或静默刷新冻结规则 |

## 反模式

- Workflow 中使用原生 channel 或执行 I/O；模型 action 不经规则即执行。
- 使用 Temporal execution RunID 作为跨执行业务幂等键；同名仓库一律视为本次成功。
- 结果未知直接重放；验证最新流水线；缺 pipeline ID 就跳过 required check。
- Token 嵌入 remote/参数/历史；用户或模型字符串作为任意 post hook。
- 摘要覆盖原文；按字节截断完整请求；必要约束仅存在于模型摘要。
- 未确认预览落真实工件；旧批准复用于新版本；终止态原地复活。
- 存本机临时文件却声称跨 Worker 可恢复；把 local、规则解析或界面模拟冒称真实外部执行。
- 在 YAML 复制正文、用文档结构通过宣称产品合规，或修改 hash 让未经批准的规则变化通过。
