# 功能：分层上下文构建

> 实体ID：feature.agent.context-building
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§2.2、§4.3、§6.1–6.3；L58–61、L183、L593、L643–727。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-014、R-015、R-018、R-019。
> 基线日期：2026-10-02。

## 目标

在模型调用前按优先级装配可追溯上下文，并真实约束预算。保护当前完整请求和结构化权威状态，使早期历史、检索和大工件不能挤掉授权、完成条件或安全规则。

## 输入

稳定 Run、definition/源版本、当前阶段/子步骤、批准/操作/约束/预算状态、完整当前消息、原文与摘要版本、允许检索材料及工件引用；模型窗口与输出/协议预留。

## 输出

ContextEnvelope、各层来源/版本、裁剪清单、token 计量方法与预算结论；超限或来源失败的拒绝。原文和权威状态不因请求裁剪被改写；模型见到的摘要始终是派生材料。

## 算法 / 流程

1. 先装固定规则与动作协议，再装 Run 身份、结构化权限/预算/完成条件和当前完整用户请求。
2. 按阶段加入可验证状态、批准与失败信息，引用同 Run 的摘要和最近消息；检索仅接纳授权来源。
3. 大工件保留稳定引用及必要片段，按检索/引用描述、旧消息、摘要的优先级裁剪，保留层级和来源。
4. 使用基线 tokenizer 或明确保守上界计算输入，预留输出与协议空间；必要层超限直接拒绝，不能切坏 UTF-8 或静默截断当前请求。

## 边界与异常

历史中的自然语言授权不能替代批准账本，摘要也不能覆盖安全规则。引用越权、缺版本、存储不可读或核实状态不明必须披露/拒绝；不同 Run 的上下文不能混合。token 估计须标明方法，展示估计不等于 enforcement；无 provider 规则模式不伪造模型消耗。

## 验收标准

构造长中文/混合文本、巨大历史和工件引用，断言请求不超预算、UTF-8 有效且完整当前消息、Run/版本与必要约束保留。必要层超限时不发模型请求；裁剪后仍可查询全部原文，跨 Run/旧版本引用被拒绝。
