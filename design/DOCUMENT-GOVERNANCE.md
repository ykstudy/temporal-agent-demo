# 文档约束与维护方式

本项目通过[有效不变量](00-invariants/INVARIANTS.md)、[功能契约](README.md#领域划分与理由)、[ADR](10-decisions/INDEX.md)和[结构Schema](_model/SCHEMA.md)形成一套规范。来源原文、当前有效规范、设计检查、产品能力及外部场景证据各有角色，不能互相覆盖。

## 一次设计变更的顺序

1. 明确要改的业务目标与范围，定位当前域、功能及相关ADR；沿结构关系查看消费者和规则适用范围。
2. 先提出具体差异与理由：旧新行为、候选方案、代价、受影响契约与验收。修正原文缺陷时保留逐字证据，新增判断标为本次裁决。
3. 在领域边界中编写公开输入/输出，不以另一域的算法、内部字段、源码示例作为依赖。消费者与提供者双方更新，关系登记同源。
4. ADR记录背景、决策、理由、备选、影响、域/功能关联与历史。规则级变更必须说明旧新不变量和例外，获得明确范围批准后才能修订冻结版本。
5. 同步结构模型中的实体/路径/关系与反向引用；正文仍唯一保存在Markdown。运行Task DAG、产品参数、对话内容不能写入文档结构YAML。
6. 执行结构检查与独立错误注入。依据具体功能验收安排后续真实行为验证；文档通过只允许报告文档一致性。

实施开始前另完成 [公共契约](contracts/README.md) 的S0：Schema字段与有效功能对应、hash输入固定、模块映射和差异矩阵完整、正负样例离线通过。然后按 [阶段路线](IMPLEMENTATION-PLAN.md) 推进。公共JSON Schema独立于文档entities/relations；模型图只通过有关功能/ADR定位其说明，不复制对象payload进YAML。

一般文档改写在已授权范围自主完成。本次用户已授权纠错补漏，新基线是审校后的规则；不是对原文错误逐字冻结。冻结后，不变量修改须有新的明确规则修订范围与ADR，普通排版或模型整理不构成改规则授权。

## 文件与引用的约束

- 原始 `docs/PRODUCT-GUIDE.md` 保留，完整字节SHA-256独立登记；参考文件不重写成当前有效规范。
- 一个功能一个文件且唯一域归属，固定八节；正文依赖只能指向另一功能 `#输入` 或 `#输出`，逆向关系同时登记。
- 一个ADR一个稳定编号，固定八节，至少关联一个域和一个功能；后续废弃/替换保留历史，不复用编号。
- 实体只含id/type/name/path及功能domain；关系只有from/to/type/必要contract；约束是结构检查目录与来源/不变量hash，不复制运行规则正文。
- 路径使用项目内相对链接和现存中文锚点；路径越界、悬空、未登记文件、内部章节依赖都失败。
- 原文中的实现示例只通过来源阅读，不因示例存在成为跨域公开接口。

## 冻结与摘要更新

校验器只读取和比较hash，绝不修复规则或自动刷新摘要。首次本轮基线经过裁决和交叉审校后登记。后续授权修订应保留旧摘要/版本及ADR，在确认具体新规则后手动计算新字节摘要，形成可审查差异；不能在检查失败时为“变绿”直接替换hash。

```sh
python3 design/_model/check.py --json
python3 design/_model/check.py --self-test --json
```

错误注入全部在自动清理的临时副本里，既不编辑来源，也不改变冻结规则。类型/白名单/章节/链接/契约比对始终执行；checks列表是检查目录，不是可以禁用内置约束的开关。

## 证据分类

| 类型 | 能证明什么 | 不能推出什么 |
| --- | --- | --- |
| 逐字来源与SHA | 本次输入及引用未被替换 | 原设计没有错误 |
| 文档结构检查 | 标识、引用、冻结、模型/正文一致 | 状态/权限/重试实际执行正确 |
| 临时错误注入 | 校验器能拦截已列反例 | 所有未来错误都被证明不存在 |
| 单元/接口测试 | 特定实现和测试场景 | live GitLab/模型/浏览器/生产运行通过 |
| 真实集成/故障注入 | 特定代码时点与环境的运行事实 | 后续修改或整个产品均完成 |
| 浏览器用户路径验收 | 可见交互和权威结果连通 | 未覆盖的模式、环境和第三方行为 |
| 公共Schema文档自检 | Schema有效、引用可解、正负结构样例符合预期 | 服务已提供该版本、跨对象语义/权限/hash内容正确 |

每次运行证据同时标明docs_ready、contract_ready、path_verified或live_verified的具体范围。结构差异逐项关闭并附证据，不能把旧路径计数或使用手册字段转化为规范符合性；决定见 [ADR-046](10-decisions/ADR-046-contract-first-implementation.md)。

早期文档阶段的保留决定已有后续授权修订；当前按 [ADR-045](10-decisions/ADR-045-agent-model-validation-separation.md) 删除参考运行耦合并实现独立 Agent，保留离线结构模型。产品内真实验证不得被外部场景调用器取代，范围与证据见[实现状态](../docs/analysis/IMPLEMENTATION-STATUS.md)。设计文档批准、模型审阅apply和运行副作用批准必须按scope区分。
