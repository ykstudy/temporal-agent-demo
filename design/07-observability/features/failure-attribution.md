# 功能：失败归因与恢复提示

> 实体ID：feature.observability.failure-attribution
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§8.1、§8.2、§8.3、§10、§13。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-006、R-010、R-021、R-022、R-024。
> 基线日期：2026-10-02。

## 目标

把失败定位到可采取行动的责任边界，保留原始原因和证据，使用户知道需要补充输入、修正方案、恢复依赖或核实外部结果，避免用重复重试掩盖问题。

## 输入

动作校验拒绝、权限与输入错误、Activity 超时和心跳、外部响应、业务验证失败、未知结果台账，以及 Run 阶段、原操作身份和脱敏诊断证据。

## 输出

稳定错误类别、发生步骤、影响对象、是否可重试、待补条件与建议动作；未知外部结果附核实入口，用户取消保留独立原因，不归为系统失败。

## 算法 / 流程

优先采用权威执行器和外部确认事实，区分输入、模型协议、授权、工具、运行基础设施、业务验证和结果未知。按错误类别与剩余预算决定有限读取重试、阻塞、修订或终止；把错误与原命令、批准及操作串联。提示只说明可执行的下一步，任何恢复命令仍交给工作流重新校验。

## 边界与异常

网络断开、超时和取消可能留下已发生副作用，不能直接显示“未创建”或“已回滚”。认证与限流错误不是资源不存在；永久错误不自动重复写入。模型解释仅是建议，不能覆盖原始错误。无法唯一归因时记录不确定性和缺失证据，隐藏秘密与敏感响应。

## 验收标准

注入权限拒绝、永久输入错误、临时读取失败、构建失败和外部写入断线，归因与恢复入口各自正确。未知结果核实前无第二次写入；用户取消保持 CANCELLED 语义，错误提示可定位原记录且不泄漏秘密。
