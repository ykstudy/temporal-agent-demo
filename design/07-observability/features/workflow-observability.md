# 功能：工作流可观测性

> 实体ID：feature.observability.workflow-observability
> 来源：[原设计](../../../docs/PRODUCT-GUIDE.md)：§5.1、§5.3、§10.1、§10.2。
> 审校：[裁决记录](../../../docs/analysis/REVIEW-DECISIONS.md)：R-002、R-013、R-021、R-024。
> 基线日期：2026-10-02。

## 目标

向运维与前端提供可解释的工作流状态、活动进度和指标，明确每项数据的来源、单位与同步边界，避免把心跳、排队或模型描述呈现为业务完成。

## 输入

权威阶段与业务版本、执行链检查点、Activity 调度及尝试事件、心跳和超时、批准与阻塞原因、已完成业务结果及审计引用。

## 输出

当前阶段、更新时间、活动尝试与最后心跳、批准等待、阻塞原因和关联证据。指标包括成功/失败 Run 数、Activity 重试数、验证失败数、总耗时毫秒、有效业务轮次数，并标明计数口径。

## 算法 / 流程

从 Query 检查点读取业务状态，以 Activity 事件补充尚未提交的执行进度；展示两者各自更新时间。成功和失败计数只来自首次终止裁决，重试计数只计首次尝试后的实际调度，验证失败计数来自独立验证结论。总耗时从 Run 创建到首次终止裁决，包含暂停和阻塞；轮次按受理的用户需求身份计数，排除助手回复、控制命令和重投。执行链切换不重置业务累计值。

## 边界与异常

心跳表示 Activity 仍上报存活，不证明外部写入完成。缓存、连接中断、检查点落后必须可见；PAUSED、BLOCKED 与 CANCELLED 不混入失败指标。没有 Temporal 数据时显式标注执行模式及不可用信息，不能伪造历史。展示层只读，不能由指标回写阶段。

## 验收标准

以一项成功、一项失败、暂停、取消和实际重试场景核对指标事件来源与单位。跨执行链累计值不重复；Activity 运行时 Query 与进度来源明确分开，断线和过期数据不会继续显示为实时成功。
