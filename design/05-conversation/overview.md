# 对话与确认域

> 实体ID：domain.conversation
> 来源：[原设计](../../docs/PRODUCT-GUIDE.md)：§2.2、§4.2、§5.4、§6、§13。
> 审校：[裁决记录](../../docs/analysis/REVIEW-DECISIONS.md)：R-002–003、R-011、R-014–015、R-018、R-022–024。
> 基线日期：2026-10-02。

## 职责

让用户通过一个对话工作区创建和跟进项目 Run，保存完整原始对话、展示结构化方案与执行证据，并把明确操作转为带身份和版本的命令。会话是交互组织，Run 是独立业务执行身份；消息、摘要、方案、工件各有稳定来源和生命周期，不能因 UI 重载或 Temporal 执行链切段而混淆。业务方案/授权范围的 source_version 与普通阶段进度的 state_sequence 分开；proposal_version 内容不可变更。

## 边界

本域不裁决运行阶段，不调用 git 或 CI 写接口，也不把自然语言“接受”直接变成批准。方案预览不产生真实项目文件；确认请求必须交编排复校。原始 JSONL 记录保持追加，模型摘要只用于工作上下文。设计结构认知模型是版本化文档审阅工具，其单用户本地 apply 与项目创建的运行确认是两个独立范围，不互相赋予执行权限。

## 与其他领域的关系

编排提供 Run 状态、命令接收和门禁结果；Agent 提供澄清、方案语义和有来源的摘要；技能提供未应用模板预览及已登记工件；治理保护身份、并发、文件路径与权限；集成和审计提供准确仓库、流水线及验证证据；前端只按本域的结构协议渲染与发送用户选择。跨域只连接公开功能契约。

## 按改动节奏划域的理由

对话展示和组件会随交互设计演进，消息身份、原文保存与确认语义则必须长期稳定。集中管理消息与版本引用，能够在更换 renderer、增加组件或压缩上下文时保持旧会话可读可审计；将文件存储单列功能，避免前端变化同时改变持久化和恢复保证。会话管理与 Workflow 执行链分开，减少 Temporal 升级对用户可见历史的影响。
